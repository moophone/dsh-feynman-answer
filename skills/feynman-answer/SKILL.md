# 费曼五段式回答

五段不是装饰，是**理解链条**：结论先落地，论点供检验，总结收线，启示转成动作，
奥卡姆把整段压到不能再压。每段各干一件不同的事，谁替谁干活就说明那段该删。

## 什么时候用

**用**——回答的目的是让人**听懂**：讲清一个概念、解释一个原因、比较两个方案、
说明一段代码为什么这样写、复盘一次故障、给出一个判断并交代理由。

**不用**——回答的目的不是让人听懂：

- 一行确认、状态回执、报错原文转述（「已部署」「测试通过」「这是日志」）。
- 纯执行报告：改了哪些文件、跑了什么命令、结果如何。这类用表格或列表即可，
  硬套五段会把三行信息撑成三十行。
- 用户在追问细节、只要一个数字或一个代码片段。
- 用户明确要求别的格式（表格、清单、直接改代码）。

判断标准只有一句：**删掉五段骨架后信息有损失吗？** 没有就不用。

## 五段骨架

标题逐字照抄，顺序不许换，序号不许省。标题后不要加冒号、不要改写同义词
（「总结」不写成「小结」，「启示及未来行动指南」不写成「启示」）。

```
## 1.先说结论

## 2.相应论点核心内容（前有序号）

## 3.总结

## 4.启示及未来行动指南

## 5.奥卡姆剃刀总结
```

### 1.先说结论

一到三句，**用大白话说人话**。读者只看这一段也该知道答案。

- 先给判断，再给理由：`能用，但只在 X 条件下`，而不是 `这取决于若干因素……`。
- 不许出现「可能 / 也许 / 视情况而定」而不带条件。有条件的结论就写条件本身。
- 不铺垫背景、不复述问题、不写「这是个好问题」。

### 2.相应论点核心内容（前有序号）

**编号列表**（`1.` `2.` `3.`），每条一个独立论点，能单独被反驳。

- 每条 = 一句断言 + 支撑它的最小机制（为什么成立 / 哪来的 / 反例在哪）。
- 一条只放一个论点。一条里塞三个论点，读者就无法逐条检验，这段就白写了。
- 按重要性排，不按发现顺序排。第一条要是「不承认这条，结论就塌」的那条。
- 需要证据就贴证据（文件路径、命令输出、数字），不要写「经测试」「一般来说」。
- 三到七条为宜。超过七条通常意味着该拆成两段，或者结论本身太含糊。

### 3.总结

不是把第 1 段抄一遍，也不是把第 2 段缩写一遍。

- 干的事：**指出第 2 段那些论点共同指向的那条主线**——它们为什么是一件事而不是七件事。
- 长度一到三句。若总结只是复述，说明第 2 段没提炼够，回去合并。

### 4.启示及未来行动指南

从「知道了」转到「接下来做什么」。每条必须**可执行且有触发条件**。

- 动作 + 对象 + 时机：`下次改 deploy.mjs 前先跑 --check`，而不是 `要注意校验`。
- 分三类写，没有就省掉：**现在该做什么** / **什么情况下该改主意** / **别再犯什么**。
- 这条最容易写成空话。检验法：把这条贴给三天后的自己，他知道第一步点哪里吗？

### 5.奥卡姆剃刀总结

整段压成**一句话**——删掉所有可删的限定、类比、举例之后仍然成立的那句。

- 一句话，不编号，不分点。
- 它是「如果只准记住一件事，记这句」。
- 不是第 3 段的缩写，是第 3 段的**剥皮**：第 3 段说清主线，这段说清主线里最硬的那颗核。

## 常见走形

| 走形 | 症状 | 改法 |
|---|---|---|
| 五段齐全但空洞 | 每段都有，读完没多知道任何事 | 删掉第 2 段里无法被反驳的条目 |
| 结论含糊 | 第 1 段以「取决于」开头 | 把条件写进结论本身，条件即结论 |
| 总结复读 | 第 3 段≈第 1 段换词 | 改写成「这些论点共同说明……」 |
| 行动是口号 | 第 4 段全是「注意 / 关注 / 重视」 | 每条补上对象和触发时机 |
| 剃刀不剃 | 第 5 段是长句复述 | 压到 25 字以内，砍掉所有从句 |

## 与其他格式的关系

- 需要展示产物（文件、图、表、代码）时，产物照常贴，五段包在它外面说明它意味着什么。
- 纯执行类回答不套五段，但**若用户问「为什么这么做」**，就从那一刻起按五段回答。
- 用户点名要别的格式时，用户赢。五段是默认值，不是规矩。
